# Modifications to upstream files

Policy. Expansion's files are modified only where a hardware assumption
cannot be isolated by link-time substitution, build-time filtering, or a
shim in `platform/`. Every modification is guarded by `PLATFORM_NATIVE` alone
(`#if PLATFORM_NATIVE` or `#if !PLATFORM_NATIVE`, never combined with
another macro; where upstream's own condition or the pointer-width test
`__SIZEOF_POINTER__` is also needed it is nested inside the guard, or follows
it as `#elif`), is as small as it can
be, and has a row in the table below with the file, the reason, a summary
of the diff, and the stage that added it (the "Since" column: M1 the research and the first documents, M2 the 32-bit boot, M3 the input replay and the save, M4 the test runner, M5 the debug-menu gate, M6 the audit of every row and the contribution rules, M7 the 64-bit build, M8 the Windows build; "Review 2026-10-14" is the code review of that date, "Review 2026-10-15" the review of the tree before the repository was published; a row can name several). The GBA build must produce
the same ROM before and after (check with `make compare` where
applicable, and `make check` always). A modification that changes GBA
behaviour is a bug.

When upgrading expansion (see `UPGRADING.md`), every row is re-verified:
the guard still applies, the surrounding code still has the assumption,
and the modification still compiles on both targets. Rows that become
unnecessary are removed, not left behind.

Flag for 64-bit: a row marked "64-bit" needs attention in the 64-bit
work, for example because it fixes a pointer width or an address
range.

Assembly. In the assembled data the guard is `.ifdef NATIVE_POINTER_SIZE_8`,
which `Makefile.native` defines (`--defsym`) for the 64-bit build only, so
it implies `PLATFORM_NATIVE`; the GBA build and the 32-bit build assemble
the `.else` branch, which is upstream's text. Assembly has no `__LINE__`,
so no `#line` follows these blocks.

Line numbers. The GBA ROM embeds `__LINE__` in assertion messages, so a
guarded block that adds lines to a `src/` file must be followed by
`#line N`, where N is the upstream line number of the first unchanged
line after the block, taken from `git show rhh/<tag>:src/<file>` (or
`main`), never from the physical line of the edited file, and
accounting for any earlier `#line` in the same file. Verify by
preprocessing with and without `-DPLATFORM_NATIVE=1` and comparing the
line markers at a few anchor lines after the block; the GBA ROM's sha1
must not change. Put the `#line` immediately before that first unchanged line, after any
blank line the block added. Where a guard can replace a blank line on each
side of the original (`#if !PLATFORM_NATIVE` / `#endif`), no `#line` is
needed. The lines of an `#else` branch itself carry the numbers the block's
extra lines give them unless the branch starts with its own `#line`; only a
`__LINE__` on such a line would show it, and the ROM's sha1 proves none
does. Headers carry `#line` where a `__LINE__` is evaluated in the header
itself (`include/test/test.h`, `include/script.h`); the width-guarded
headers (`include/metaprogram.h`, `include/librfu.h`,
`include/load_save.h`, `include/task.h`) carry it too, so that their
later lines keep upstream's numbers in diagnostics.
